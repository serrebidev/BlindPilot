# Changelog

Readable release history for BlindPilot. When adjacent releases were part of the
same fix stream, they are combined with a version range such as
`v0.3.6-v0.3.7`.

## v0.20.6 - 2026-09-02

- The New Session dialog says what it is doing, and does not say things twice. Three findings from holding its speech to the same standard as the install wizard's: the help under the name field claimed that leaving it empty "lets Hermes name it after your first message" — true for a Hermes session, false for a local Claude, Codex, FreeBuff or opencode one, where the first message names the tab and Hermes is not involved in naming anything; the remote-mode explanation — the session will run on another machine, so folders on this computer do not apply — was a StaticText, which no screen reader announces when a dialog opens, so the person landed on the name field having heard none of the context that makes the dialog's shape make sense; and a refused folder was announced explicitly and then shown in a modal dialog that announces the same sentence again. The help now says "Leave it empty to let the first message name it", true in every mode for every backend; the remote explanation is spoken when the dialog opens; and the refusal is said once, by the dialog that asks for a correction.

- The test suite is hermetic on a machine Hermes has been installed on, and fully green under `-W error` again. The official installer sets `HERMES_HOME` persistently, and two test fixtures that point every history store at a throwaway home never cleared it — so on a machine where the installer had run, fifteen history tests and one settings-file test answered with the machine's own conversations instead of the ones the tests had built. The fixtures now delete `HERMES_HOME` the way they already delete `CODEX_HOME`, `XDG_DATA_HOME` and `OPENCODE_DATA`. One real leak surfaced by the same standard: `mint_ws_ticket` caught an `HTTPError` without closing the response body it carries, which warns "Implicitly cleaning up" at collection time — a failure under `-W error` and an open response stream in real use until then. It is closed now. The full suite is green with `-W error` for the first time since Hermes was installed on this machine.

## v0.20.5 - 2026-09-02

- A session that runs on another machine can now be named, instead of asking for a folder this computer cannot answer for. New Session in remote mode asks for a name first — the only field this machine can answer — and an optional folder on that computer as free text, with no Browse button, since a picker here would browse the wrong computer and an inert control costs a screen reader user a stop in the tab order. The path travels exactly as typed: no `expanduser`, no `abspath`, no `expandvars`, each of which resolves against the wrong filesystem. A remote Hermes validates a path against its own disk and, when it cannot honour it, silently substitutes its own directory — a folder browsed to on this machine once passed validation and the conversation ran somewhere else, in a tab named after a directory it was never in. `session.create` reports the directory it resolved, and when that is not what was asked for the conversation now says so: "Hermes could not use `C:\Users\g\Desktop\projekt`, so this conversation is running in `/home/ubuntu`" — deliberately quiet when the folder was honoured or none was asked for. A tab with neither a name nor a folder now reads "New session" rather than nothing, the one label a screen reader cannot tell from its neighbour, and `/status` says the folder was "chosen by the Hermes running this session" instead of printing `Folder:` followed by nothing.

- A session keeps the name it was given, past its first message. A conversation is normally named after its first message — the title Recent Conversations lists it under — and nothing checked whether it already had a name of its own: a session named for its subject and sent "start" became "start" from then on, and with Hermes the two names then disagreed about the same conversation, since a name given at creation is stored with `title_source='user'` and is not overwritten by the automatic one. A name belongs to one conversation, so it is dropped wherever the tab becomes a different one — clearing it, reopening a Hermes conversation, restoring one from disk, or changing backend once a conversation exists — but not before the first message, where there is nothing to leave behind and a name typed seconds ago must survive picking a backend. Whitespace counts as no name, so a tab cannot end up with a blank label. The fix lives where the label is recomputed, not in the label function itself, which was correct all along; each of the five changes has a test that fails without it, and an unnamed session is still named by its first message.

- Transport fakes can no longer lie about being connected. Every fake in the suite now runs against the real `Transport` semantics: a stream that has ended — pipe closed, socket gone — must turn `connected()` False within a time budget, while a peer that is merely quiet stays connected, the distinction one `None` cannot make on its own. The registry is walked structurally rather than by name, so the next fake is caught at write time instead of on a runner in another country — it found its first unregistered fake on its own first run, and it caught itself silently skipping on Linux, a guard disappearing where it is needed most because a missing wx module raised `BaseException`, not `Exception`. Four fakes claimed connection after their stream ran out and six let `send()` succeed after `close()`; all of them now end their stream and refuse writes the way real pipes and sockets do.

## v0.20.4 - 2026-09-02

- Hermes is found after its own installer installs it. The first end-to-end run of the new install path succeeded — exit code 0, "hermes command ready", a complete install under `%LOCALAPPDATA%\hermes` — and then BlindPilot reported "hermes was not found afterwards", because discovery did not know the layout the installer actually writes. Three facts from the captured installer output, each now pinned by a test: the launcher lands in `%LOCALAPPDATA%\hermes\bin`, beside the managed uv it installs; `HERMES_HOME` is set persistently, so a process that was already running when the installer finished — this application, during a wizard-driven install — still carries the old environment and must find the default location on disk rather than trust it; and the gateway's venv launcher is `Scripts\hermes.exe` on Windows, where the fallback only ever looked for the POSIX `bin\hermes`. `find_hermes_cli` checks the installer's bin directory and the Windows venv layout, `hermes_source_root` looks under `%LOCALAPPDATA%\hermes` when `HERMES_HOME` is stale, and the search PATH gains the installer's bin directory before it runs. Verified against the real install the wizard produced: launcher, interpreter and source root all resolve, and `hermes_installed()` answers True.

## v0.20.3 - 2026-09-02

- Every backend the registry holds now installs from the setup wizard on Windows, macOS and Linux, Hermes included. It is not on npm, and until now that meant the wizard could not install it at all: the captured session behind the last release showed the whole journey — an install that ran nothing, a report that npm could not be installed on a machine that has npm, and an instruction spliced mid-sentence. Hermes' own official installers are the answer, and they are the same shape as the Claude installer this application has driven for months: `iex (irm https://hermes-agent.nousresearch.com/install.ps1)` through PowerShell on native Windows, `curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash` through curl on macOS, Linux and WSL2 — no administrator rights, no Node.js, and prerequisites that already ship with the platform. The install follows the same discipline as Claude's: the installer's output streams into the accessible log as it happens, the exit code is treated as advisory, and a working `hermes` launcher afterwards is the fact that counts; the install directory is put on the user's PATH so the CLI works in a terminal too. The Update path had the same hole and is fixed with it: updating a found Hermes used to fall through to npm and report that npm could not be found for a backend with no npm package, where it now re-runs the official installer, which upgrades in place. npm is never named in any Hermes branch — it has nothing to do with that install, and naming it sends the user after the wrong thing. Sixteen tests, failing-first: per-platform installer argv, missing prerequisites by name, binary-not-exit-code success, both routes, and what the wizard says in each branch.

## v0.20.2 - 2026-09-02

- The setup wizard no longer offers to install a backend BlindPilot cannot install, and install failures are said in whole sentences. One press of Install Hermes, captured from NVDA, spoke four lines within three milliseconds: "Installing Hermes. This usually takes under a minute.", "npm could not be installed, so BlindPilot cannot install Hermes automatically" — untrue, on the machine it was captured on, which has npm — and an instruction to "install Hermes yourself using See https://hermes-agent.nousresearch.com/docs", a sentence with another sentence's fragment spliced into its middle. The wizard's check asked whether Node was installable before asking whether the backend comes from npm at all, and its install helper answers a managed-Node sentinel for any backend — so Hermes, which ships its own installer and is not on npm, was offered an install that runs nothing, reports the npm line, and loops back to the same offer. The check now asks npm-membership first: a backend BlindPilot does not install gets its own guidance — where its instructions are, and Check Again once it is there — and no Install button. `install_backend` refuses such a backend in its own terms before touching npm, pressing a stale Install button refuses at once instead of promising a minute it does not have, and the failure message carries the install command unspliced, built from parts that are sentences on their own. Every backend in the registry is pinned by a test: no splice, command always present.

## v0.20.1 - 2026-09-02

- The warning-clean sweep now excludes a virtualenv however it is named. The test that compiles every module so no `SyntaxWarning` can reach a release carried a hard-coded list of directory names — `.venv`, `venv`, `build`, `dist`, `__pycache__`, `.test-tmp` — and a contributor whose virtualenv was `.venv-win` and whose staging directory was `dist_new` had 4,652 files of installed wxPython swept in and compiled as parametrised cases, which is where a reported suite of 5,682 came from against a repository with 1,001 tests. The exclusion matches a prefix on directory components relative to the swept root now: a virtualenv called anything at all is excluded, a file whose own name starts with dist is still source, and a checkout living under a path that contains one of these words — pytest's own basetemp among them — is not discarded wholesale. A real directory layout, written out as a test, pins it. Diagnosed by michaldziwisz in the Hermes PR, whose suite totals had been quietly counting their own site-packages.

## v0.20.0 - 2026-09-02

- Stay connected through a long turn, and say so while it lasts. A turn that produced no output for about twenty seconds lost its connection: the socket's connect timeout applies to every later read, so an ordinary quiet stretch — a build, a test run, a model thinking, a rate limit being waited out — raised a timeout that was treated as a dead connection and ended the thread reading it. With nobody reading, nobody answered the server's keepalive pings either, so the server closed a connection that was perfectly healthy. Measured against a server pinging as Hermes does: the reading thread died after twenty-one seconds of quiet before, and survives three minutes of it now, with the next message answered normally. A read that times out is no longer confused with a peer that has gone away, while a peer that really has gone away still ends the turn as before.
- Say what a long turn is doing instead of leaving it silent. Waiting was unnarrated for up to fifteen minutes, which is indistinguishable from a hang for anyone who cannot glance at the screen. A quiet turn now reports itself about once a minute, saying how long it has been working and which step it is working on, and Hermes' own account of what it is doing — the process it started, the conversation being summarised to free up room — is read out as it arrives instead of being discarded. A turn that is reporting steps of its own is left alone.
- Notice a connection that dies mid-turn within seconds rather than at the end of the idle limit, and say why it went, rather than sitting out a quarter of an hour of silence first. Sending into a connection nobody is reading is refused instead of reported as success — that success was a silent loss, with the answer never arriving and nothing said about it.
- Send an attached file to Hermes, rather than a line naming where it is. A path is all the other backends need, because they read this machine's disk; Hermes can be running in WSL or on another computer, where that path either points at nothing or — worse, with two machines that mount a drive the same way — at a different file of the same name. The file itself now travels, and the answer is about the file that was picked. The filename is sent separately from the path, because a Hermes on Linux does not read a backslash as a folder separator and would otherwise keep a Windows path as one long filename. A file that cannot be sent stops the turn and says which file and why, instead of an answer about something the model never received.
- Read a Hermes answer while it is still being written, instead of waiting for the turn to end. The answer arrived in fragments that were collected and delivered in one go, so a fifteen-second turn was fifteen seconds of silence over a stream the server had been sending from the third second. Whole sentences are released as they finish, never a half-written word, because half a word read aloud is what makes a run sound broken. The last clause goes out when the turn ends.
- Turn the working sound down, or off, from Options. It is a cue under a second long that repeated end to end for the whole turn: about nineteen times on a fifteen-second turn, eighty on a minute-long one, over the answer being spoken, with nothing anywhere to change it. Three choices now: continuous as before, every few seconds (the default, ten seconds, adjustable from two to a hundred and twenty), or off, which leaves the send and received sounds in place. Choosing one applies to the turn already running rather than the next one.
- Keep one Hermes connection for a conversation instead of opening another for every message. Each message used to pay for a login, a handshake and a session resume, and left the server reaping the session it had just abandoned. The connection is read continuously, which is what answers the keepalive pings a Hermes bound to a public address sends. Without that, a held connection is closed from the other end within about half a minute. It is let go when the conversation is left, when a turn is cancelled, and when it is found dead, in which case the next message opens a fresh one exactly as before.
- Run Hermes Agent as a fifth backend, chosen from the Model menu like the others. It reads its answers, its reasoning, and every tool it runs into the same navigable rows, reopens past conversations from Recent Conversations, compacts in place, and can be steered or stopped while it works.
- Drive a Hermes running on another computer, from Options, Remote Hermes: a name, a port, and either a session token or a username and password, with a Test connection button that says whether they work before anything is sent. A server on a home network can be worked with from the desktop without opening a terminal. Leave it off and the copy installed here is used, with nothing to configure.
- Find and run a Hermes installed in WSL from a Windows desktop. Nothing in Windows' PATH points at one, so the wizard used to report that Hermes was not found on a machine with a working Hermes. The folder you are working in is translated, so Hermes runs where you expect.
- Reopen past Hermes conversations with Ctrl+H, filtered to the current folder like the other backends. Hermes keeps every conversation in one store rather than a file each, and a Hermes in WSL keeps it inside the distribution, which the dialog now reads.
- Say why a remote connection failed in terms of what to do about it — a refused key, nothing listening, an unknown name — rather than reporting that it failed. The key never appears in those messages, or anywhere else that is read aloud; it is kept in a file of its own rather than among the display settings.
- Ask each backend what it supports instead of naming the ones that do not. The permission picker, the effort levels, the compaction command, and the wizard's closing summary were all deciding by backend name, which quietly gave a new backend controls its protocol has no answer for.
- Stop telling users to install Node.js for a backend that does not come from npm, and stop running an interactive sign-in hidden with no keyboard attached to it — which fails immediately and was reported as a failed sign-in. A backend whose setup asks questions now opens a real terminal window and says to come back when it is answered.
- Hermes' reasoning channel carries the spinner it draws for a terminal, not the model's reasoning. That is left out, since read aloud it is noise, and the reasoning it does report is shown instead — once, not twice when a short answer arrives as its own reasoning.
- Go back to any conversation a Hermes knows, and join one that is running, from Hermes Conversations (Ctrl+G). Recent Conversations reads this machine's disk, which holds nothing for a Hermes on another computer, so a conversation started in a terminal on that machine — or by a messaging channel — could not be reached at all. The list is asked of Hermes itself and names where each conversation came from; the ones its gateway is running are marked, and opening one of those replays the transcript and then follows the turn in progress, which can be steered. Hermes keeps one event stream per conversation, so joining a live one moves that stream to this window, and both the list and the dialog say so before it happens rather than leaving it to be discovered.
- Steering and stopping a remote Hermes turn now reach it. Both were addressed by the stored conversation id, which the gateway answers with "session not found" — it takes the id of the live session — so on every conversation with a Hermes reached over the network, Steer and Stop did nothing at all while the window reported the instruction as accepted. Measured against a live gateway: the stored id is refused, the live one queues the guidance.
- A reopened Hermes conversation is remembered by an id that outlives the gateway. Resume answers with a handle belonging to the running gateway process and, separately, the durable conversation id; reading the wrong one meant a reopened conversation worked until that gateway restarted and then could not be found again, with nothing saying why.
- Up in the prompt moves the caret instead of leaving the field. It entered the newest response whenever the caret was on the first line, which is exactly where somebody reviewing a multi-line prompt keeps arriving: reading back what you had just typed, or moving up through a dictated paragraph, threw focus into the response list mid-sentence, with the text still there and the caret gone. Up and Down now behave as they do in every other multi-line field, and the responses are still reached by Ctrl+R, by Shift+Tab, or by Ctrl+Up for anyone who had built the habit.
- Hermes Conversations is offered only while Hermes is the backend. It asks a Hermes for its own conversations, so with another backend chosen there is no Hermes in the picture and the item answers a question nobody is asking. It is removed rather than greyed out — unlike Compact and Connect, which are commands for this conversation that a backend cannot perform and so say something useful when disabled. This one is not unavailable, it is irrelevant, and an irrelevant item still costs an arrow press in a File menu already at its ten-item ceiling. Removing it takes Ctrl+G with it, so the chord does nothing rather than opening a dialog that would immediately report there is nothing to ask. Chat mode hides it too, having no backend conversation to reopen.

## v0.19.2 - 2026-09-02

- Shift+Tab into the session tab strip is no longer a dead end. Arrowing along the strip changed the session, and showing the newly selected conversation took focus off the strip and put it in that page's prompt — so the first arrow press threw you out of the tab control and the second never reached it. The strip keeps focus through a session change now, exactly as it did before the strip and the pages became two controls, and the native tab control announces the tab it moved to.
- A Tab that BlindPilot routes but does not actually move is handed back to Windows instead of being swallowed. Every boundary between the Mode picker, the tab strip and the conversation is crossed by hand, and a hand-routed key that asks an unfocusable control for focus used to consume the keypress and leave the user where they were, however many times they pressed it. Focus is checked after the move, and native traversal gets the key when it did not happen.
- Tab out of the tab strip lands in the Prompt when the responses list cannot take focus, rather than nowhere.

## v0.19.1 - 2026-09-02

- Choosing a backend in the setup wizard no longer announces it a second time. The wizard said "Backend selected: …" through the app's own speech channel the moment the choice control had finished announcing its newly focused value natively, so a screen-reader user heard the same backend twice — once from the control, once from BlindPilot — on every change of the picker that drives the rest of the wizard. It was the only announcement in the application that narrated a native control's own selection; the others all report app events, and none of them is missed. `_on_backend_choice` has exactly one caller, the choice event itself, so there was never a programmatic selection that relied on the extra line.

## v0.19.0 - 2026-09-02

- The first-run wizard no longer loops silently on a profile the settings file cannot be written to. `_save_config` caught `OSError` and did nothing with it — no return value, no log line, nothing said — and completing the wizard is recorded by writing the settings, so a roaming profile on an unreachable share, a full disk, or a locked directory put somebody through the whole wizard, CLI install and browser sign-in included, on every launch, with nothing connecting that to a file nobody can write. The same write carries `backend`, so a Codex or FreeBuff user was also dropped back to the Claude default and sent through the Claude checks: the one visible symptom pointed at the wrong cause. It now returns whether it wrote, logs the reason, and the wizard says plainly that its settings were not saved and it will ask again.
- The settings write is atomic now. It truncated the file before filling it, so an interruption partway left a half-written one that `_load_config` cannot parse — it returns `{}` and every setting resets together, `setup_complete` among them. The failure that loses one setting should not be able to lose all of them; it is written to one side and moved into place.
- A CLI can no longer run a program it finds in the folder it was pointed at. Every provider CLI is started with `cwd` set to the user's project folder and shells out constantly — git, node, npm, sh — and Windows has historically searched the current directory for those, so a `git.exe` committed to a cloned repository was what ran when the agent asked for git. The folder is usually not the user's own work: the ordinary use of this application is to clone a repository and ask an agent about it, which means running commands inside a directory whose contents somebody else chose, and a screen-reader user gets no glance-at-the-folder moment in which to notice a file that does not belong. `subprocess_env` sets `NoDefaultCurrentDirectoryInExePath` there, the documented mechanism, inherited by everything the CLI goes on to start, and leaves untouched the PATH construction that lets an npm shim find its sibling `node`.
- The release token goes to the job that publishes, not the one that builds. `permissions:` at the top of a workflow file applies to every job, so `contents: write` was held by the build — which installs `requirements-build.txt` and runs PyInstaller on three runners, a great deal of third-party code, none of which needs to write to the repository. The workflow defaults to read now, and the one job that needs write asks for it on its own.
- Closing a tab mid-turn no longer freezes the window to cancel the turn. `cancel_worker` ran the backend's cancel on the UI thread — for opencode that is an abort POST whose thirty-second timeout is per socket operation rather than a budget — and then joined for three seconds more, and a window that has stopped pumping messages is silence to a screen-reader user. A tab close hands the cancelling to a daemon thread and returns; quitting still waits, because a CLI that is not killed outlives the application, but all the cancels are started first and one budget is shared across them instead of three seconds apiece.
- The working sound stopped when a tab closed mid-turn only if the worker's completion event reached a panel that no longer existed. `_drain_worker_events` discards everything once the panel is gone — by design — which also threw away the one event that stops the sound, and the sound is not the panel's to lose: every tab shares the frame's earcons, and on Windows the loop is process-wide. It played on with nothing left alive to stop it. Closing stops it directly now.
- A FreeBuff turn cut off at its hour was delivered as if it were the answer. The turn loop ends either because FreeBuff finished or because the hour ran out underneath it, and from the code after the loop those were indistinguishable, so a partial answer went out through the same `_on_complete` a finished one uses: announced as the answer, kept in the transcript as the answer, with nothing to suggest it was not the whole of it. A turn stopped at the deadline now says so first and keeps what it had got to; one with nothing to show says what stopped waiting.
- A failing Codex turn reported why it died without the line that says why. stdout reaching EOF and stderr's last line are different threads on different pipes, so the panic, the unauthorized, the out of memory — the one line worth having — was still in flight when the failure was composed, and the reason was lost differently each time. The last words are waited for now, bounded at one second.
- Deferred callbacks no longer touch dialogs that are already gone. The wizard's `_check_cli` and `_check_signin` land an event-loop iteration after the wizard closes; its install callbacks arrive a minute into an install whose Cancel and Escape stay live and which nothing tells to stop; and a prompt read-back scheduled a second and a half earlier can outlive the tab it belonged to. Each says nothing when it arrives homeless, in the same `if not self` terms `_drain_worker_events` already used for the same reason.
- Claude Code edits are narrated with their size: "Editing server.py, 3 lines added, 1 removed." For somebody listening, the count is the only sense of scale available — "changed a line" and "rewrote the file" are the same sentence without it — and it is a real diff through difflib opcodes, so replacing a twenty-line function to change two of its lines is a two-line edit. The count goes in the line the tool call already has, never a second utterance; a half that is zero is left out; Write says how many lines it wrote; MultiEdit adds its edits up; Claude Code only, because its Edit carries both strings and the others do not.
- `/status` is in the menu bar. Model > Session Status… sits beside Backend and Model, which is the menu about what this conversation is set to, and a new test requires every command in `_BLINDPILOT_SLASH_COMMANDS` to name the menu entry it lives under or record why it deliberately has none — adding a command without deciding fails there instead of shipping something findable only by being told.
- Model > Backend Settings… lists every settings file BlindPilot knows of for the current folder, says which are really there and which the CLI has not written yet, and opens the chosen one in whatever the person already edits files with. The scope is in the label because the two project-level Claude Code files differ only in whether the repository carries them, and opening the wrong one silently is how personal settings end up committed to a repository that is not theirs. It creates nothing — these belong to the CLIs, which write their own — and a missing file offers the folder it belongs in instead of inventing one that would do nothing while looking like it did.

## v0.18.0 - 2026-09-02

- Four things the screen reader said at the wrong moment, from an accessibility audit (PR #23). A rebuilt response list threw its contents away and put the reader's row back afterwards, and putting it back is the part that speaks — once per drained batch, so during a turn the row somebody was reading was announced back to them every few hundredths of a second, underneath the narration of the turn itself. Rows are only ever appended during a turn, so the usual case appends now: no rebuild, no selection to restore, nothing that speaks. A refresh that changes shape — a search, a new turn, a response replaced by its parsed form — still rebuilds and still restores the selection, because there it really was lost.
- Dictation puts text in the prompt with no keystrokes, so a pause timer read the whole prompt back — and `EVT_TEXT` fires for typing too, so pausing to think mid-sentence read it over the top of the character echo the screen reader had been giving all along. A keystroke adds one character and has already been spoken; only bulk schedules a read-back now, typing afterwards cancels a pending one, and it reads what arrived rather than the whole field, so dictating a second sentence onto a long prompt no longer replays the first.
- A search reported its outcome to the status bar, which no screen reader reads unasked, and with no hits it did not move focus either — a quiet empty list, indistinguishable from a dropped keystroke. It is announced now, and still mirrored to the status bar.
- Enter on Cancel in the past-conversations dialog opened the selected conversation instead: `EVT_CHAR_HOOK` fires before the focused control sees the key, and the dialog closed either way, so the only sign was what appeared afterwards. Enter is handed back when the focused control is a button; Escape is unchanged, and the other five char-hook dialogs were checked for the same habit.
- The append fast path in that rewrite trusted the model's record of what it displayed to equal what the control shows, and two ordinary paths break that equality. `clear_conversation` empties both lists while the control still holds the old transcript — Ctrl+Shift+N, the menu item, `/clear`, `/new` — so the cleared conversation stayed on screen and the next turn appended underneath it; and `apply_view_mode` shows whichever responses control Options asks for, only the visible one of which is ever filled, so switching to the text view came up blank whenever nothing new had arrived since the last refresh. Both rebuilt on 0.17.0, which is why the rebuild branch is still there: the append now happens only when the control's own count agrees with the record, and anything else falls to the rebuild. `restore_history` resets `_displayed` the same way and survives only because it always runs on a brand-new panel; the count check covers it anyway.

## v0.17.0 - 2026-09-02

- BlindPilot no longer stops a Claude Code that has already answered. A user reported it after a turn that had worked perfectly: "BlindPilot stopped Claude Code: it had not finished shutting down 30 seconds after it went quiet." Nothing had gone wrong — the sentence was BlindPilot's own, and the bug was in the fix 0.11.1 shipped. A turn finishes and delivers its answer; BlindPilot closed the CLI's stdin, waited for it to exit, gave up and killed it, and on Windows `Popen.kill` is `TerminateProcess(handle, 1)`, so it read back the exit code it had just caused and reported it. A correct answer, a thirty-second pause, and an alarming sentence about a process doing its job.
- The wait's clock restarted whenever the CLI wrote to stderr, reasoning that one still writing is still working. That reasoning is sound for a CLI dying mid-turn — it is writing the traceback there, and that traceback is the only thing BlindPilot can offer. It is worthless at the end of a healthy turn, because a CLI shutting down cleanly has no errors to write. The clock never restarted, and what shipped was a flat thirty-second timeout describing itself as patient. The waiting was the mistake, not its duration: once the answer is in, no exit code changes what anybody hears. A turn that answered now neither waits for its process nor kills it — `poll()` is free, so an already-exited process is noted, and one still running is left to a daemon reaper thread that collects it (bounded at five minutes, silently, because the turn it belonged to ended correctly long ago). A bad exit code the CLI reached on its own is still reported; one BlindPilot caused no longer exists to report. The thirty-second wait stays on the failure path, where its stderr signal is real, and both docstrings now say which path is which.
- What leaving it cost: every turn slower than thirty seconds to shut down was killed partway through writing the session file the next `--resume` reads, and partway through stopping its MCP servers rather than cutting them off. A run that fanned out background agents has the most to put away and is the most likely to be interrupted. Four new tests drive a process that answers and then shuts down silently — which is what the old fake could not express; before they were written, the old test passed by simulating the one thing that never happens.

## v0.16.0 - 2026-09-02

- FreeBuff no longer cuts a word at the wrong letter when finishing an answer. FreeBuff reads its answer off a terminal, so working out which part was never spoken means comparing what was drawn against what was written, letter by letter: `_keyed` reduces both to a comparable form and records where each kept character came from. The two ran out of step, because `casefold()` is not length-preserving — German `ß` folds to `ss`, Turkish `İ` to two characters, the `fi` ligature to two — while the position list got one entry per character of the *input*. `"Straße"`, six characters, produced a seven-character key and only seven positions including the sentinel, so `positions[len(key)]` indexed past the end. Two failures came out of it: an answer read out in full raised `IndexError` (at least it was loud), and an answer read out in part was cut at the wrong letter, silently — `_unspoken_tail("Grüße", "Grüße gehen raus")` returned `"ehen raus"`, so a German user heard a word with its first letter missing and was given no reason. One position per character of the key fixes both, and the sentinel keeps a fully-spoken answer indexable.
- Found by property testing, not by reading. Hypothesis had already been run at the segmenter and found nothing across 18,000 examples — that code is solid; pointed at this arithmetic it produced a falsifying case in seconds, on ordinary German text no hand-written example had thought to use. The properties are kept only for this file, a few hundred examples and about two seconds, because it is the arithmetic that earned them and the next edit deserves the same treatment; hypothesis is not spread further than the place that paid for it. Example-based tests written from what the property test produced sit alongside, so the specific regressions are named and readable.

## v0.11.1 - 2026-09-02

- BlindPilot no longer produces the exit code it then blames on Claude Code. At the end of a turn it closed the CLI's input and waited five seconds flat before killing it, and on Windows `Popen.kill()` is `TerminateProcess(handle, 1)`, so a killed process reports exit code *exactly* 1 — which the next line reported as "Claude Code exited with code 1". The number and the ending were both BlindPilot's, attributed to the CLI, and nothing in the message distinguished this from a genuine failure, which is why the reports of it have been so hard to place. Five seconds was the wrong measure as well: shutting down is not instant, a session is written to disk and MCP servers are torn down, and a run that has just kept a fan-out of agents alive is the one with the most to put away — so the 0.8.0 fix that let those agents finish made this fire *more* often, not less. Waiting now watches for silence rather than counting seconds: while the CLI is still writing it is still working, so the clock restarts whenever it says anything, and only a process quiet for thirty seconds is stopped. The count of agents still going was read from each result event alone with nothing remembered between them, so an event carrying no `subagent_stats` returned zero, closed stdin and killed the lot — the original bug of 0.8.0, restored by a field simply being absent. Plain `{"type": "result"}` is the ordinary shape of a turn, so this was not a hypothetical. What was last known now stands until an event actually says otherwise. Two smaller errors in the same counting are fixed with it, both of which hang a turn forever rather than ending it early: `True` is an `int` in Python, so `started_in_background: true` counted as one agent that could never settle, and counts now refuse bools; and a `killed` field arriving as anything other than a dict was ignored entirely, leaving those agents counted as running for good.

## v0.6.3 - 2026-08-28

- Every backend now starts with a PATH that can reach Node. An application opened from the macOS Dock inherits launchd's PATH and nothing else, and every provider CLI npm installs is a `#!/usr/bin/env node` shim, so a child handed that PATH died on "env: node: No such file or directory" before printing anything anyone could act on. FreeBuff's pseudo-terminal was the one place that passed no environment at all, which is why FreeBuff never ran on a Mac while the others did. The environment is now built once and carries the PATH a login shell would have given, and everything that starts a CLI uses it: the sign-in, the auth probes, the version checks, and npm itself.
- What we start is now stopped. Half of these CLIs are launchers rather than programs - npm's codex and freebuff are Node scripts running the real agent as a child - and killing the launcher left that child running, still holding its lock and still waiting on a sign-in nobody was completing. Children now start in a process group of their own and are stopped as one, and the group is only signalled when the child is demonstrably its leader, because a child still sitting in our own group would have us signal ourselves.
- A terminal that died during start-up reported a guess. It now reports its own last words, which is the only part of it anyone can act on.
- FreeBuff's model picker selected the right model again. FreeBuff has dropped deepseek-v4-pro, and a remembered model was offered whether or not the installed release still had it, so the picker was driven looking for a row that never appears and the message was lost after five seconds. Worse, the picker parsed three of five rows, because FreeBuff's display names disagree with its ids about where a version letter goes - `mimo/mimo-v2.5` is drawn "MiMo 2.5" - and navigation counts arrow presses as the distance between two positions in that list, so a missing row silently selected the wrong model for every model below it. A dropped model is no longer offered, and one that goes missing mid-run falls back audibly instead of costing the turn.
- The progress earcon plays once. It watched an event that the next turn cleared while the previous thread was still inside `wait()`, so one cue became several playing over each other - and a player that could not play the file at all spun spawning processes as fast as the machine allowed.
- The packaged smoke test now fails on macOS if AppKit did not make it into the bundle. AppKit is how anything is said to VoiceOver, and a build that packaged everything else and dropped it starts, runs, and is silent.
- Windows behaviour is unchanged: the process-group flags are empty there, the login shell is never asked, and the pywinpty spawn is untouched.

## v0.4.0 - 2026-08-19

- opencode is a backend, and it does everything the others do: streaming answers, steering a turn while it runs, stopping one, permission modes, compaction, and reopening a past conversation to carry on with it. It is picked from File → Backend like the rest, and installed, updated, and signed into from the same wizard.
- It is driven through the headless server its own terminal interface talks to, rather than through one process per turn. BlindPilot starts one server, shared by every tab, on the loopback interface behind a password generated for that run, and reads each turn off its event stream. That is the only surface that exposes everything at once, which is why nothing about opencode had to be left out.
- `/model` covers every model opencode can reach, named `provider/model`, with the reasoning variants each one offers. The list is read per directory, because a project's own `opencode.json` can pin a model or turn providers off, and an effort a model does not offer is never sent with it.
- `/connect` is opencode's own command, carried over as a dialog: every provider it knows, the connected ones first, with an API key or a browser sign-in depending on what the provider offers. Providers that need an account id or a self-hosted address ask for it in opencode's own words. It is also the Connect a Provider step in the setup wizard, because opencode's command-line sign-in is a terminal prompt nobody using a screen reader can answer.
- Permission modes reach opencode as rules it enforces rather than as instructions to a model: plan mode selects opencode's own plan agent and denies edits outright, accept-edits allows edits while a shell command keeps the normal safeguard, and default leaves opencode's own configuration alone. A request that still needs answering is answered from the mode, and a question opencode stops to ask mid-turn is declined and reported — unanswered, it would hold the turn open for good.
- opencode's own slash commands are run as commands rather than typed at the model: the picker offers whichever ones the current directory has — its built-in `/init` and `/review`, plus anything the project defines — and a `/name` it does not recognise is left alone, so a sentence that happens to start with a slash is still a sentence.
- Past opencode conversations are read straight out of its SQLite database, read-only, titled by their first message where opencode has not titled them itself. Subagent conversations are left out of the list: nobody had those.
- Steering an opencode turn is answered from what the window already knows and delivered on a thread of its own. It used to wait on a request, and on the window's own thread — a window that stops answering is a window a screen reader cannot describe.
- Every conversation opencode has had in a directory is offered, not just the ones among the most recent few hundred. Its conversations for every directory share one database, so a limit on rows read was a limit on how far back this project's history went.
- opencode's sign-in check no longer reads any `*_API_KEY` in the environment as a signed-in opencode. Plenty of programs set one and have nothing to do with opencode; a confident yes that turns into a wall at the first message is worse than an unconfirmed you can walk past.
