# BlindPilot 0.29.3

The README catches up with the code, and two tests now hold the two together.

- Muse Code became a backend in 0.26, but the README was only updated for Command Code in 0.28. It went on saying BlindPilot runs six coding agents, its Backends table listed six, and there was no by-hand setup entry for Muse. Every one of those places now names Muse Code: the opening sentence, the count (seven), the wizard paragraph, the by-hand setup block with the one-line installer and `muse login`, the Backends table, and a new paragraph explaining how BlindPilot drives it — over Muse's own MSP protocol, reached inside WSL on Windows through the same bridge Hermes uses, with tool approvals and the agent's questions put in front of you, past conversations reopened by session id, and Meta's Muse Spark refusal spoken instead of a turn that hangs.
- Nothing noticed the README drift because no test read the README. One does now: it reads the file the way a person does and fails whenever a backend or Chat provider exists in the code without a mention — every backend label must appear in the opening sentence, the by-hand setup block and the Backends table, the count stated in words must match the number of backends the code ships, and every Chat provider must appear in the supported-providers sentence. Written before the fix, it named all five places Muse Code was missing, and it will name the next backend's omissions the day one lands without its documentation.
- The sound-cue tests built their earcons from the developer's real config.json and then asked the live working-loop setting. On a machine whose config has the working cue switched off, the loop-starts test failed and the loop-stays-off test passed without proving anything. The fixture now pins the master switch, every cue, and the loop mode, so those tests describe the earcons and not the machine they happen to run on.
