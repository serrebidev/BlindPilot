# BlindPilot 0.29.27

Installing Hermes from the setup wizard now works on a Windows computer whose AppData folder is kept in sync by OneDrive, a roaming profile, or a similar program. People on those machines got as far as "Downloading Python 3.14", then an error they could not act on, and BlindPilot told them the installer had finished without errors but left no `hermes` behind.

- What was actually failing: Hermes' own installer starts a small tool called uv to download the Python it needs, and uv keeps those Python installs in your Roaming AppData folder by default. Roaming is the folder a sync client takes over, and Windows will not walk through one of those synced folders to put a program there. It refused, uv gave up, and the error said so in whatever language Windows is set to -- on the machine that reported this, in Polish -- while the installer around it still reported success.
- What BlindPilot does now: it asks Hermes' installer to put those Python installs in your Local AppData folder instead, which is where uv already keeps its downloads anyway and which no sync client touches. This applies both when you install Hermes and when you update it, and if you have already told uv where to keep its Pythons yourself, BlindPilot leaves your choice alone.
- On a computer where the roaming folder is clearly inside a synced one, BlindPilot also tells Windows about the new location, so the same bootstrap that runs when you type `hermes update` in a terminal finds its Python instead of failing the way the install just did. You hear that it has done this, and where the files went.
- When an install still ends without a working `hermes`, BlindPilot no longer stops at "exit code 0 but hermes was not found". It says that Windows refused to place Hermes' Python inside a folder a sync program owns, and names the one setting that moves it somewhere Windows will allow.
