# BlindPilot 0.29.11

Two fixes for long turns: a Hermes on another computer behind a load balancer or a login proxy now connects, and a Command Code turn that runs out of turns keeps the work it finished instead of losing it.

- A Hermes reached over the network was logging in and then throwing the session away before connecting. Every client that works sends the session it was just given - the dashboard in a browser, Hermes' own desktop app, the other apps reaching the same address. BlindPilot sent none, so a load balancer that places a connection by cookie, or a proxy that authenticates by one, refused the one request that mattered while letting the browser through. It now sends that session, matched the way a browser matches a cookie.
- A refused connection says which layer refused it. Hermes answers an upgrade it turns down with an empty 403 and no body; anything in front of it writes its own error page and names itself. BlindPilot tells the two apart now, and no longer sends you to check that your proxy allows WebSockets - the one thing a browser dashboard that works has already proved.
- Command Code's print mode stops after 100 turns by default, which is the budget for a script that pipes a question in and reads an answer out. A real piece of work spends a turn on every step, so a task that runs to the end in a terminal stopped mid-way here. BlindPilot asks for 500 turns now.
- A Command Code turn that does reach that limit no longer loses its answer. It was reported as a failure with everything the turn had done thrown away; the partial answer is kept now and the turn says it was cut off, in words that are spoken whatever your narration mode.
