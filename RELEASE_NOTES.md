# BlindPilot 0.43.5

FreeBuff no longer opens a terminal window, and a message sent at launch is no longer lost inside FreeBuff's first second.

- No terminal window from FreeBuff. The previous release stopped BlindPilot claiming a console of its own, but the library that created FreeBuff's hidden terminal allocates one in whatever process hosts it: starting FreeBuff gave BlindPilot a real console window, titled with BlindPilot's own executable, and the watcher that hides such windows could only hide it after it had appeared and taken your screen reader's focus -- the "terminal" announcement right after switching to FreeBuff. BlindPilot now creates the hidden terminal itself through Windows' pseudoconsole API, which allocates nothing in BlindPilot at all, and the library is out of the build. Verified in a windowless process against the installed FreeBuff 0.2.26: no console exists before, during, or after a launch or a full turn. A watcher still hides any console window FreeBuff's own tools raise while they work.
- Messages are held until FreeBuff can actually take them. The current FreeBuff paints its typing box about a second before it accepts input, and anything typed in that second disappears without a trace -- BlindPilot's hold, which waited for a "reconnected" line in FreeBuff's log, released early because a launch whose chat folder had not appeared yet counted as ready, and current FreeBuff never writes that line in any case. The message is now held until the chat log shows the sign-in milestone both FreeBuff releases we measured write during boot, and it is then sent and answered normally. The same live check that previously ended with "FreeBuff dropped its session" now answers in about thirteen seconds.
- How FreeBuff is driven is otherwise unchanged: upstream still offers no headless or JSON mode (the open request is CodebuffAI/freebuff#947), so the hidden terminal drives its screen while the finished answer is read from the chat files FreeBuff itself writes.
