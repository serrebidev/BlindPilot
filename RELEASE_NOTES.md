# BlindPilot 0.43.4

FreeBuff no longer opens a terminal window, and a message in a project with `.agents` files can no longer stall on a prompt nobody can see.

- No terminal window from FreeBuff. BlindPilot used to claim a console for itself before starting FreeBuff's hidden terminal, and Windows creates that console already visible: a window titled with BlindPilot's own executable flashed when BlindPilot started, when you switched to FreeBuff, and at your first message, and it could take your screen reader's focus with it. The hidden terminal FreeBuff actually runs in is a pseudo-terminal, which creates no window at all, so BlindPilot no longer claims a console. A watcher still hides any console window FreeBuff's own tools raise. Verified against the installed FreeBuff 0.2.26: it starts, reaches its prompt, and finishes with no console window at any point.
- FreeBuff starts with `--trust-agents`. That is FreeBuff's own switch for unattended runs. Without it, a project carrying `.agents` or `mcp.json` files stops on FreeBuff's "do you trust this project" prompt inside the hidden terminal, where nobody can answer it, and the message died after two silent minutes. BlindPilot already runs every agent in the folder you chose without asking, so the prompt is now answered at launch instead.
- How FreeBuff is driven is unchanged, because upstream still offers nothing better: the FreeBuff CLI has no headless or JSON mode (the open request is CodebuffAI/freebuff#947), so the hidden terminal drives its screen while the finished answer is read from the chat files FreeBuff itself writes. If upstream ships a print mode, BlindPilot can drop the terminal then.
