# Reference Parity Stage Three Implementation Plan

**Goal:** Show provider usage/costs, add local Ollama chat, and compact long Chat conversations, with attachment-preserving edit/resend covered by tests.

**Architecture:** New `accessible_ai/providers/ollama.py` beside the other providers and `provider_reports.py` for usage adapters. Reuse `Database.branch_conversation` for compaction's preserved history. Keep generation/compaction network work on workers.

**Spec:** `docs/superpowers/specs/2026-11-14-reference-app-parity-design.md`, staged release 3.

## Global Constraints

- Unknown usage/cost values stay unknown; never present estimates as bills.
- GUI callbacks stay under the ADR 0001 50 ms budget; network calls run on workers.
- Compaction preserves the full history in a separate conversation; the original is never mutated under a worker. A retry never deletes the old response before a replacement succeeds.
- Threshold estimates are labeled as estimates; reliable context data (not heuristics) is what enables automatic behavior.
- No new dependencies; stdlib plus existing provider seams only.
- Menu additions go to submenus (top-level menus are at the ten-item ceiling).
- Before commit: Ruff check, Ruff format check, full `pytest -q -W error`, bare `mypy`, startup smokes.

## Task 1: Usage and balance reports

- [ ] `accessible_ai/providers/provider_reports.py`: `UsageReport` (provider, checked_at, usage, limit, remaining, balance, note). Adapters: OpenRouter via `GET /api/v1/key` (`data.usage`, `data.limit_remaining`, `data.is_free_tier`) and `GET /api/v1/credits` for balance when available; Ollama lists local models with no usage. Every adapter returns unknowns explicitly; network failures become a report with an error note, never a guessed number.
- [ ] Usage dialog from the Chat menu ("Usage Report…") listing the current account's report; refresh button; results on a worker with cancellation-safe delivery.
- [ ] Tests: fixture adapter responses parse to the right numbers; unknown fields stay unknown; network failure yields an error note, not zeros.

## Task 2: Ollama local chat

- [ ] `PROVIDER_OLLAMA = "ollama"` in `accessible_ai/models.py` (`PROVIDER_LABELS` + `PROVIDER_ORDER` entry). Builtin default base `http://localhost:11434`, API mode chat completions.
- [ ] `OllamaProvider` (OpenAI-compatible surface at `/v1`): model discovery from `GET /api/tags` (local, no key); chat via existing `generate_chat_completions`. No API key required.
- [ ] Factory + config wiring. Accounts UI treats Ollama as keyless (no required-key error).
- [ ] Tests: factory returns the Ollama provider; model discovery parses `/api/tags`; keyless account creation path.

## Task 3: Chat compaction

- [ ] `Database.compact_conversation(conversation_id, keep_last_n) -> int`: atomically create a copy conversation carrying a summary placeholder system prompt plus the newest `keep_last_n` messages with attachments; the original stays untouched. Returns the new id.
- [ ] Compaction summary generated by the current account on a worker, then installed as the new conversation's system-prompt snapshot; failure keeps the original and says so.
- [ ] Chat menu "Compact Conversation…" action with a keep-last control; the full history remains reachable as the uncompacted conversation. Optional auto-compact threshold uses a labeled character estimate only, off by default.
- [ ] Tests: original rows unchanged; new conversation has the summary plus exactly the last N messages with attachment bytes; failure path preserves the original.

## Task 4: Presets and edit/resend coverage

- [ ] The Ollama provider entry is the local preset: choosing it in the account picker fills the localhost address and needs no key. Document other compatible endpoints beside the built-in table (no new UI).
- [ ] Tests: edited history items keep their attachment bytes; retry restores text and attachments into the draft without sending.
